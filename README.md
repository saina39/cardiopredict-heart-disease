# CardioPredict — Heart Disease Prediction Web App

An end-to-end machine learning web application that predicts heart disease risk
from 13 standard clinical measurements, built with **Flask**, **scikit-learn**,
**XGBoost**, and a glassmorphism-styled frontend with dark/light mode.
## Task Alignment

This project was built for **Task 4: Disease Prediction from Medical Data**, which
allowed a choice between three UCI ML Repository datasets — Heart Disease, Diabetes,
and Breast Cancer. The **Heart Disease dataset** was selected deliberately for this
implementation, as cardiovascular disease is the leading global cause of death and
the dataset's 13 features (symptoms like chest pain type, blood test results like
cholesterol and fasting blood sugar, and vitals like resting blood pressure) map
cleanly onto the task's suggested feature types.

All four algorithms named in the task brief were trained and benchmarked:
**Logistic Regression**, **Random Forest**, **SVM**, and **XGBoost** — see the
[Model Info page](#3-run-the-web-app) (`/about` route) or `model/model_info.json`
for the full comparison.

## 2. Train the model

The dataset is already included at `dataset/heart.csv`. Run:

```bash
python train.py
```

This will:
1. Load and clean the dataset (handles missing values, duplicates, and non-numeric entries defensively).
2. Generate 5 EDA charts into `static/images/` (class distribution, age distribution, correlation heatmap, cholesterol vs. heart rate, chest pain type breakdown).
3. Train **Logistic Regression**, **Random Forest**, **SVM**, and **XGBoost**.
4. Compare accuracy, precision, recall, F1, and ROC-AUC for each model.
5. Select the best model automatically (by accuracy, tie-broken by ROC-AUC) and save:
   - `model/best_model.pkl`
   - `model/scaler.pkl`
   - `model/feature_names.pkl`
   - `model/model_info.json` (metrics for every model, for the "Model Info" page)
6. Save a model-comparison bar chart and a confusion matrix for the winning model.

On this dataset, the pipeline currently selects **SVM** with **~83.6% accuracy** and **0.88 ROC-AUC** — you'll see the exact numbers printed in your terminal (results can vary slightly by environment/library versions).

## 3. Run the web app

```bash
python app.py
```

Visit **http://localhost:5000** in your browser. Pages:
- `/` — Home, with an animated hero and live model stats
- `/predict` — Clinical input form (GET) → risk result page (POST)
- `/about` — Full model comparison table + EDA charts
- `/api/predict` — JSON API endpoint (see below)

### JSON API usage

```bash
curl -X POST http://localhost:5000/api/predict \
  -H "Content-Type: application/json" \
  -d '{
    "age": 63, "sex": 1, "cp": 3, "trestbps": 145, "chol": 233,
    "fbs": 1, "restecg": 0, "thalach": 150, "exang": 0,
    "oldpeak": 2.3, "slope": 0, "ca": 0, "thal": 1
  }'
```

Response:
```json
{
  "success": true,
  "prediction": 1,
  "label": "Disease Detected",
  "probability": 0.6419,
  "risk_percent": 64.19
}
```

**Field reference:**

| Field | Meaning | Range |
|---|---|---|
| age | Age in years | 1–120 |
| sex | 1 = male, 0 = female | 0–1 |
| cp | Chest pain type (0 typical, 1 atypical, 2 non-anginal, 3 asymptomatic) | 0–3 |
| trestbps | Resting blood pressure (mm Hg) | 60–250 |
| chol | Serum cholesterol (mg/dl) | 100–700 |
| fbs | Fasting blood sugar > 120 mg/dl (1 = yes) | 0–1 |
| restecg | Resting ECG result (0 normal, 1 ST-T abnormality, 2 LV hypertrophy) | 0–2 |
| thalach | Max heart rate achieved | 60–250 |
| exang | Exercise-induced angina (1 = yes) | 0–1 |
| oldpeak | ST depression induced by exercise | 0–10 |
| slope | Slope of peak exercise ST segment (0 up, 1 flat, 2 down) | 0–2 |
| ca | Major vessels colored by fluoroscopy | 0–4 |
| thal | Thalassemia (0 normal, 1 fixed defect, 2 reversible defect, 3 other) | 0–3 |

## 4. Deploy to Render

1. Push this project to a GitHub repository.
2. In Render, click **New → Web Service** and connect the repo.
3. Render will detect `render.yaml` automatically, or set manually:
   - **Build command:** `pip install -r requirements.txt && python train.py`
   - **Start command:** `gunicorn app:app`
   - **Environment variable:** `FLASK_DEBUG=false`
4. Deploy. Render trains the model during the build step so `model/*.pkl` exists at runtime (these files are not committed to git — add `model/` and a `.gitignore` if you'd rather commit pre-trained artifacts instead of retraining on every deploy).

> Tip: Training only takes a few seconds on this dataset, so retraining on each deploy is cheap and guarantees the model always matches the current `train.py`.

## Design notes

- **Frontend:** glassmorphism cards over a navy/teal gradient, an animated ECG line hero, an animated risk gauge on the result page, dark/light theme toggle (persisted via `localStorage`), and client-side validation that mirrors the server-side rules in `predict.py`.
- **Backend:** `predict.py` is fully decoupled from Flask so it can be reused or unit tested independently. `app.py` handles routing, form/JSON input, and 404/500 error pages.
- **Not a medical device.** This project is an educational ML/web-dev demo. Predictions should never be used for real diagnosis — always consult a licensed clinician.
